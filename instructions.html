Run it and check it

This page says how to run graphview, and what to check in version 4.1. Each line to check says what to do, and under it what to expect. Tick a line when it holds; this browser keeps your ticks. The README says what every control and key does.

1. Install

You need Node.js 22.17 or later, and a terminal in the repository's folder.

npm ci

Run it once, and again whenever package-lock.json changes.

2. Run it

One command starts the shell, which plays a host around the viewer.

npm run dev

Open the address it prints. That is localhost:5173/graphview/, unless the port is taken. Ctrl and C in the terminal stop it.

  • The headline reads "Sample graph, 81 units, 84 relations, no issues". The host tools stand on the left. The viewer fills the rest with its bar, its canvas and its side bar.

The checks below start from the default settings, with motion on. In Settings, Reset all brings the defaults back; Export first keeps your own values. The server keeps each browser's settings under data/, which git leaves out.

To see the built shell instead, run npm run build:server, then npx vite preview --config shell/vite.config.ts, and open localhost:4173/graphview/.

3. Check by hand

Twenty-four lines cover what version 4.1 changed for the person at the screen. Start from the sample graph. If the camera jumps where it should glide, look at Motion in Settings: it follows the system's request for reduced motion.

The camera

  • The unit stays under the pointer while the picture grows and shrinks.

  • The camera glides back to the whole graph in about half a second. It does not jump.

  • The picture pans in one smooth move, three steps long. Each press adds to the move under way.

  • The picture zooms in by two steps, then glides back to the whole graph.

  • The drag turns the view, and the keys turn it by even steps. 2D glides back to straight above.

  • The picture follows the pointer softly, glides on after you let go, and comes to rest by itself. Without Glide it stops where you let go.

Words on the canvas

  • A small label names the unit, and its type where it has one. It goes when the pointer moves on.

  • The label reads "Relation between … and …" on the line, and "Keypair from … to …" on the chevron.

  • The canvas soon says "Laying out 2,000 units…", and goes on saying so until the picture comes. That took about ten seconds on the machine the report names.

  • The sample graph shows at once. It does not wait for the layout to end.

The side bar

  • The unit becomes the root. The Inspector opens again and comes into view, with the unit's name.

  • The side bar lists the results, and the heading Search counts them.

  • A banner says that the graph breaks the graph rules. Its button, Show 7 issues, brings Data issues into view, and that heading counts 7.

  • The side bar comes back as you left it: the same sections open, at the same width.

  • The side bar hides, and it is still hidden after the reload. Panels brings it back.

  • The key moves to the search field, and typing opens the side bar with the results. The first Escape empties the field; the second gives the keys back to the canvas.

The look

  • The mode in use, 2D or 3D, is filled. Panels is filled while the side bar shows, and Host while the host tools show.

  • The button fills and reads Unpin, and the setting shows under Pinned settings in the side bar.

  • Text stands clear of the borders. Ticks and sliders are slate grey, not the browser's blue.

  • Under "Keypairs by type", the table shows each name in full. A long name wraps; none is cut.

  • The page turns dark, and every line above still holds.

  • The side bar becomes a drawer that starts closed. Panels and Settings keep to the right edge of the viewer's bar.

Speed

  • The picture comes without hulls and without a wait for a layout. Dragging and the wheel stay smooth.

  • The table gives your machine's first picture and frame times. Section 4 of docs/report.md has the numbers to compare them with.

4. Check by machine

Three commands check the types, the format, the tests and the builds.

  • npm run check

    svelte-check finds no errors, Prettier accepts every file, and all 360 unit and gate tests pass. Folders kept beside the work belong in .git/info/exclude first, or two of the checks fail on them; section 7 of docs/assessment.md has the lines. 

  • npm run e2e

    It builds the shell with its server, serves it, and runs 118 tests; all pass. That took about four minutes on the machine the report names. 

  • npm run build

    It writes dist/module, dist/shell, dist/server and dist/package, and ends without an error.

The browser tests need a Chromium. npx playwright install --with-deps chromium downloads Playwright's own. A Chrome the machine already has serves as well: GRAPHVIEW_CHROMIUM=/usr/bin/google-chrome npm run e2e.

npm test runs the checks and the browser tests in a row. After a push, the workflow checks.yml runs it too.
